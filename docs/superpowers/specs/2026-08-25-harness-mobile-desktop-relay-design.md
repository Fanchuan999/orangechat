# Daddy Harness 双端独立编程助手设计

日期：2026-08-25
状态：用户已确认架构，待实现计划与开发
目标仓库：`Fanchuan999/orangechat`（Daddy / OrangeChat 衍生版）

## 1. 目标与定位

将现有手机端 DeepSeek Harness 从“能打开的编程工作台”完善为独立的移动编程助手，并新增一条可从 Daddy 手机派发任务到 Windows 电脑 Claude Code 的安全通道。

Daddy 仍是陪伴聊天应用；手机 Harness、电脑 Claude Code 和 Daddy 聊天分别保持独立的模型、会话、工具、配置与记忆。Daddy 只在用户明确要求执行任务，或用户同意其建议时，向指定执行端发送最小任务简报。

本期最终形态：

```text
Daddy 聊天 / 手机任务入口
  ├─ 手机 Harness（Termux + Debian + DSH）
  │    └─ 手机文件、Termux、Daddy 插件与移动端开发任务
  └─ 电脑 Claude Code（Windows PC Relay）
       └─ 电脑项目、VS Code 项目、长时间构建与批量任务

加密任务信箱负责两端离线排队、状态回传与手机远程批准。
```

## 2. 已确认的产品决策

1. 手机 Harness 是独立编程助手，不是 Daddy 的隐藏子代理。
2. 用户可以从手机给电脑派任务并查看电脑任务进度。
3. 电脑不需要一直开机：离线任务保留在队列；电脑开机、登录且联网后才接收。
4. 电脑 Relay 在 Windows 用户登录后后台启动；锁屏可继续运行，睡眠、关机或注销时不执行任务。
5. 首次访问一个新的电脑工作目录，需要在 Daddy 手机确认；已批准目录可以继续用于普通任务。
6. 电脑任务的首次批准优先在手机完成，不要求用户在电脑旁点击确认。
7. 普通电脑任务只需一次手机批准。若任务开始时已明确包含高风险操作，该次批准同时覆盖启动与已声明风险；若执行中临时产生新的高风险操作，再向手机请求一次具体确认。
8. 手机 Harness 新增“全权自动”审批档：普通操作不反复询问；删除、批量覆盖、安装系统包、上传密钥、`git push`、访问外网、跨目录批量操作仍需用户确认。
9. 代码小屋本期不继续扩展 UI；继续使用现有任务看板与工作台入口。
10. 手机与电脑的任务通信采用独立的、端到端加密的 Supabase 离线信箱，不要求处于同一 Wi-Fi。
11. Supabase 信箱不保存项目文件、完整聊天、人设、Ombre 记忆、API Key 或未加密任务正文。
12. 电脑第一版执行器使用已验证存在的 `claude.cmd`（Claude Code `2.1.204`），不要求在电脑额外安装 Harness。
13. 同一电脑工作目录只允许一个运行中任务；不同目录可并行的能力不属于第一版。
14. Harness 原生网页的图片/文件入口直接补到工作台本身，不通过一个新的 Daddy 插件伪装上传能力。
15. 在实现 PC Relay 前必须先完成一个只影响电脑的可行性原型；它不阻塞手机 Harness 原生附件功能。
16. 远程任务只引用已登记的 `workspaceId` 和可选的 `relativeScope`，不把 Windows 绝对路径放入任务信封。
17. 一个逻辑任务与一次实际执行尝试必须使用不同标识；Relay 租约过期不得自动启动新执行。
18. 高风险审批必须在同一条 Claude Code 非交互执行与权限工具调用中等待手机结果；不得仅生成审批卡后结束 worker，再依赖排队或 `--resume` 猜测恢复。

## 3. 范围与非目标

### 3.1 本期包含

- 手机 Harness Web 工作台的原生图片、普通文件入口。
- 固定、可重复应用的 Harness Web/服务端补丁与版本兼容检查。
- 手机 Harness 审批策略档位扩展。
- Windows Daddy PC Relay：队列领取、手机批准、调用 Claude Code、状态回传、目录锁与恢复。
- Daddy 任务路由：明确选择“手机 Harness”或“电脑 Claude Code”。
- 加密离线信箱、任务状态和自动清理。
- 手机远程显示并批准电脑任务及高风险步骤。

### 3.2 本期不包含

- 安装或维护电脑端 DeepSeek Harness。
- 控制、模拟点击或读取 VS Code 图形界面；Relay 调用的是 `claude.cmd` 命令行。
- 传输电脑上的项目文件到 Supabase。
- 电脑与手机完整会话、Ombre、世界书或人格同步。
- 让手机与电脑同时修改同一个工作目录。
- 绕过 Android、Windows、Claude Code 或 GitHub 的安全机制。
- 通用文件附件在 Harness 对话中作为模型多模态输入。普通文件是安全导入工作目录后，由 Agent 通过文件工具读取。

## 4. 总体架构

```text
                     ┌────────────────────────────┐
                     │          Daddy 手机          │
                     │ 聊天 / 任务目标 / 手机确认卡 │
                     └───────────┬────────────────┘
                                 │ 最小任务简报、批准、状态查询
                                 ▼
             ┌─────────────────────────────────────────┐
             │ 加密任务信箱（Supabase，非聊天数据）       │
             │ 任务信封 / 事件摘要 / 一次性批准令牌       │
             └───────────────┬─────────────────────────┘
                             │
               ┌─────────────┴─────────────┐
               ▼                           ▼
 ┌──────────────────────────┐  ┌──────────────────────────┐
 │ 手机 Harness              │  │ Windows Daddy PC Relay    │
 │ Termux → Debian → DSH     │  │ Windows 登录后后台运行    │
 │ 127.0.0.1:3080            │  │ 调用 claude.cmd           │
 └──────────────────────────┘  └──────────────────────────┘
```

任务路由层只传递下列字段：任务编号、目标端、任务说明、成功标准、明确工作目录、显式文件引用、约束、发起聊天窗口标识。不得自动传递完整聊天、无关亲密内容、世界书、九维状态或 Ombre 原文。

## 5. 手机 Harness 原生附件能力

### 5.1 图片

在 Harness Web 工作台的聊天输入框旁增加“图片”按钮：

1. 按钮通过已有 Android WebView `onShowFileChooser` 调起系统选择器。
2. 用户选择 PNG、JPEG、WebP 或 GIF 后，网页读取并走官方 `session.prompt` 的原生 `image` 内容块。
3. 保持官方限制：单图不超过 5 MB、每条消息最多 20 张、使用服务端已支持的图片验证与持久化链路。
4. 文件读取失败、格式不支持、超限或会话不可用时，页面显示可理解错误，不发送半截消息。

### 5.2 普通文件

Harness 当前协议没有通用二进制附件 RPC，因此普通文件不能伪装成图片或直接塞进对话消息。

工作台新增“文件”按钮，并使用受管理的服务端补丁：

1. 系统选择器返回一个文件。
2. 前端只在大小和类型预检通过后提交给本机 Harness 导入端点。
3. 服务端将内容写入当前会话工作目录下的 `uploads/`，创建时使用唯一文件名；绝不覆盖同名已有文件。
4. 导入完成后，工作台向会话插入一条明确文本，例如“已安全导入文件：`uploads/report.pdf`。如需要，请读取、分析或处理它；不要自行执行其中内容。”
5. 导入本身不执行、解压、解析或上传文件；后续读取和危险操作仍由 Harness 审批策略处理。

默认普通文件导入上限为 25 MB。超出时网页不读取、不编码、不上传，提示用户将文件放到 Harness 可见目录并明确告诉 Agent 路径，例如：

```text
/host/storage/Download/论文.pdf
```

这里必须使用 Debian/Termux 可见的挂载路径，不能让 Agent 使用 Android 的 `content://` URI。

### 5.3 补丁维护

原生附件需要修改已安装 DSH 的 Web/服务端资源，Harness 更新可能覆盖改动。因此必须提供：

- 一个固定的补丁源目录，保存在 `$HOME/daddy-harness/managed-patches/`。
- 幂等的 `apply-harness-mobile-patch.sh`：重复运行不得叠加按钮或损坏原文件。
- 版本/源码特征检查：只允许在已验证的 DSH 版本和匹配文件特征上应用。
- 自动备份被修改文件及补丁元数据。
- 不兼容时安全停止，标记“补丁需更新”，不得部分修改后继续启动。
- Harness 更新脚本在健康检查后调用补丁脚本；失败时恢复上一个工作版本或保持原工作台可用。

## 6. 手机 Harness 审批档位

Harness 设置增加独立的审批档位；它不影响 Daddy 的聊天工具、Termux Bridge、MCP 或电脑 Relay。

| 档位 | 自动允许 | 必须确认 |
|---|---|---|
| 安全确认 | 现有严格白名单，例如工作目录与极少量状态查看 | 绝大部分工具和命令 |
| 开发顺畅 | 源码查看、搜索、普通编辑、构建、测试、Lint、Git 查看类操作 | 高风险与范围不明确操作 |
| 全权自动 | 正常读写、常规开发、普通构建与测试 | 删除、批量覆盖、装系统包、上传密钥、`git push`、外网、跨目录批量操作 |

“全权自动”不是关闭安全门。每次高风险确认必须展示操作说明、目标范围、原因、取消/本次允许按钮与任务编号。拒绝后必须将“用户拒绝”回传 Agent，避免重复弹窗。

## 7. Windows Daddy PC Relay

### 7.0 阶段 0：PC Relay 可行性原型

在构建 Relay、Supabase 表或 Daddy 路由之前，先在用户现有 Windows + cc switch 环境完成一个小型、可丢弃的原型。该原型不读取或修改真实项目文件，除非用户明确选择一个测试目录。

必须实测以下内容，不能仅依据 Claude Code 文档推断：

1. `claude.cmd -p` 在后台进程中是否继承 cc switch 的认证与当前模型配置。
2. `--output-format stream-json` 的实际事件结构：可用的进度、工具调用、费用、最终结果与 session 标识字段。
3. `--permission-prompt-tool` 是否能在权限请求发生时保持同一个 Claude Code 进程和 MCP 调用存活，等待远程手机批准。
4. 手机批准后，权限工具是否可以向这一次 MCP 调用返回 `allow`，并让原始工具调用继续。
5. 手机拒绝、超时、取消、Windows 睡眠、Relay 崩溃、网络断开时，Claude 进程、session 和已产生文件各自处于什么状态。

`--resume` 只允许作为“已中断 attempt 的新尝试”恢复任务上下文的备选手段；它不得被描述为、也不得被依赖为恢复一个已中断的待批准工具调用。阶段 0 未通过前，PC Relay 不发布“远程高风险审批可恢复”的能力。

### 7.1 安装与运行

PC Relay 安装在用户明确的本地目录，例如：

```text
D:\Daddy-PC-Relay\
  relay.exe 或启动脚本
  config\
  state\
  logs\
```

安装完成后创建 Windows 计划任务：用户登录时启动、以当前用户身份运行、不要求管理员权限。电脑锁屏后继续运行；睡眠、关机、注销或无网络时不执行。

Relay 的启动命令必须显式使用 `claude.cmd`，不能依赖 PowerShell 对 `claude.ps1` 的执行策略。现有电脑已验证：`claude.cmd --version` 返回 Claude Code `2.1.204`。

首次安装包含一个最小真实调用自检，用低成本提示验证 Claude Code 和 cc switch 当前配置确实能在后台 Relay 环境中工作。未经用户同意，不执行真实项目修改。

### 7.2 任务领取与执行

1. Relay 上线后只读取属于当前已配对电脑的加密任务信封。
2. 任务只给出 `workspaceId` 与 `relativeScope`。Relay 从本地工作区登记表解析真实根目录；手机不会收到、保存或依赖该绝对路径。
3. Relay 拒绝绝对路径、`..`、UNC 路径、未登记盘符，以及解析真实路径后脱离批准根目录的范围。实现必须识别符号链接、Windows Junction 和 Reparse Point，不能仅做字符串前缀判断。
4. 若任务已过期、被取消、工作区无效、范围越界或目录被锁定，Relay 回传明确失败/等待状态，不启动 Claude Code。
5. 对首次使用的 `workspaceId` 或新增的 `relativeScope`，Relay 先把工作区的友好名称、相对范围和风险摘要发给手机，等待手机授权。
6. 用户在手机确认后，Relay 在已解析的真实目录执行 `claude.cmd`，将任务简报作为输入。
7. 标准输出、结构化事件和最终结果被裁剪、脱敏后回传；密钥、环境变量、完整文件内容不得写进信箱。
8. 同一目录存在运行中任务时，新任务排队；前一任务结束、失败或取消后才可继续。

对于 Git 工作区，Relay 在每次 attempt 启动前记录分支、HEAD、已修改路径与目录状态摘要。它绝不自动 `stash`、`reset`、`checkout` 或覆盖已有改动。未提交改动不应一律阻塞工作：只读、构建和与已改文件不重叠的任务可继续；目标范围与已有改动重叠时，手机必须收到冲突确认卡。非 Git 目录记录等价的目录基线摘要，而不伪造 Git revision。

Relay 不操作 VS Code 图形界面，但 Claude Code 对该目录所做的改动会自然出现在 VS Code 中。

### 7.3 模型选择

- Relay 维护一个“电脑默认工作模型/配置”，第一版为 cc switch 当前实际供 `claude.cmd` 使用的配置。
- 手机可选择“使用电脑默认配置”。
- 后续仅展示 Relay 已上报且实际可用的命名配置；手机不能随意输入一个未配置模型名。
- 手机 Harness 的模型配置和电脑 Claude Code 配置相互独立。

## 8. 加密离线信箱与手机批准

### 8.1 信箱职责

Supabase 仅作为离线信使，不作为编程工作区或聊天存储。它保存：

- 加密任务信封；
- 加密状态事件和短结果摘要；
- 任务生命周期元数据（任务编号、目标端、创建/更新时间、状态、过期时间）；
- 一次性批准请求与回执；
- 设备配对公钥、撤销状态与最小设备信息。

任务正文、文件名中的隐私信息与结果内容在客户端/Relay 加密后才上传。项目文件、图片、API Key、终端完整输出、环境变量和 Daddy 聊天历史永不进入信箱。

工作区的真实绝对路径只保存在本机 Relay 登记表。信箱中只出现 `workspaceId`、相对范围、用于 UI 的非敏感友好名称，以及经过加密的任务最小内容。

### 8.2 设备配对

首次在电脑安装 Relay 时：

1. Relay 生成设备密钥并展示一次性配对码/二维码。
2. Daddy 手机扫描或输入配对码。
3. 双方交换公钥并建立此电脑专属的加密通道。
4. 手机可在设置中查看、重命名或撤销配对电脑；撤销后 Relay 立即不能领取新任务。

批准回执必须与任务编号、电脑标识、风险摘要、过期时间和一次性随机数绑定，防止被复制、重放或用于别的任务。

### 8.3 手机远程批准

批准卡优先在 Daddy 手机显示，可通过应用内任务入口和系统通知进入。卡片至少显示：

- 目标电脑和工作目录；
- 任务摘要、成功标准与模型配置；
- 当前风险级别、将要执行的高风险动作（如有）；
- “执行/仅本次允许”“拒绝”“取消任务”。

普通任务：一次手机批准后启动。若任务一开始就说明了明确高风险，此次批准同时覆盖启动与该声明风险。执行中发现新的高风险时，Relay 暂停并发送第二张手机确认卡；无需到电脑再确认。

若手机长期离线或批准过期，Relay 保持暂停，绝不根据旧授权继续执行。

## 9. 任务状态与恢复

状态机：

```text
queued_offline（电脑离线）
  → awaiting_phone_approval（等待手机批准）
  → running（执行中）
  → awaiting_risk_approval（同一进程等待新风险批准）
  → completed / failed / cancelled

running / awaiting_risk_approval
  → interrupted / orphaned（睡眠、进程崩溃、Relay 中断或租约失效）
interrupted / orphaned
  → awaiting_phone_approval（用户选择创建新的执行尝试）
```

约束：

- `taskId` 是用户委托的不可变逻辑任务；每次真正启动 Claude Code 均新建 `attemptId`。重新执行绝不复用旧 attempt。
- 每个状态事件均有 `eventId` 与单调递增 `sequence`；任务创建和手机批准携带 `idempotencyKey`，网络重试不能重复创建或重复允许。
- Relay 领取 attempt 时获取 `leaseId` 与单调递增的 `fencingToken`。只有持有当前 token 的 Relay 才能写状态、提交结果或释放目录锁；迟到的旧 Relay 事件必须被拒绝。
- `expectedRevision` / `baselineFingerprint` 绑定 attempt 的启动基线：Git 目录使用 HEAD、分支与脏文件摘要；非 Git 目录使用规范化目录状态摘要。
- 任务已取消、已完成、已失败或过期后不能再次执行。
- Relay 断网时可以继续本地执行；网络恢复后按 `sequence` 补发事件。
- 高风险步骤触发时，权限 MCP 工具保持阻塞等待；它生成的手机确认必须绑定 `taskId`、`attemptId`、`actionDigest`、一次性随机数和过期时间。批准后立刻在同一调用内返回 `allow`，批准标记随即设为 `used`；拒绝则同一调用返回 `deny`。
- Windows 睡眠、关机、注销、Relay 崩溃或 Claude Code 进程退出时标记 `interrupted` 或 `orphaned`，不自动从头重跑。
- 租约到期也不得自动重新排队或启动新 attempt。Relay 必须先验证旧进程及其 session 已结束；仍无法确认时保持 `orphaned` 并让用户在手机选择重新执行或取消。
- 手机可选择“重新执行/取消”；只有阶段 0 证明真正的同会话恢复可靠后，才额外开放“继续”。
- 初始任务内容和完整结果保留 7 天后自动清理；仅保留最短状态审计摘要。等待离线电脑的任务也具有可配置过期时间，默认 7 天。

本期代码小屋维持现状：不承诺完整步骤级进度条。Daddy/Relay 先提供准确状态和简短实时进展；完成任务从“进行中”列表移除，详情可在对应工作台/任务记录查看。

## 10. Daddy 任务路由

Daddy 在用户明确委托时组织最小简报，并要求用户选择或确认目标：

| 目标 | 适用任务 |
|---|---|
| 手机 Harness | Termux、手机共享存储、Daddy 插件、移动端小修复 |
| 电脑 Claude Code | VS Code 项目、电脑文件、构建、解压/批处理、耗时编程任务 |

Daddy 不得仅凭“代码”二字自动把任务发送给任一端。用户明确说“交给手机 Harness”“让电脑做”“交给 Claude Code”，或在选择卡中确认后才创建任务。普通陪伴聊天绝不触发任务。

## 11. 错误处理与安全边界

- 电脑未开机、未登录、睡眠或网络断开：显示 `queued_offline`，不调用模型。
- `claude.cmd` 不可用、cc switch 配置失效或认证失败：显示真实错误与修复入口，不假装已执行。
- 工作目录消失、被锁、无权限或不同盘符不可用：拒绝执行并回传原因。
- Relay 读取到无效加密信封、未知设备或过期批准：丢弃并记录最小审计事件。
- Harness 补丁无法匹配当前版本：保持原工作台，标记需要补丁更新；不执行部分替换。
- 手机附件超限、格式不支持或导入失败：不创建空文件，不伪造已上传。
- 任何输出、日志、任务摘要都必须脱敏 API Key、Bearer Token、Cookie、私钥、环境变量与密码。
- 电脑执行器的细粒度高风险拦截必须在实现前以 Claude Code CLI 的真实权限/批准接口验证；若无法可靠拦截，第一版不得宣称“自动安全门已生效”，而应收紧执行权限并清楚提示限制。

## 12. 用户操作流程

### 12.1 手机 Harness 使用附件

1. 在 Daddy 打开 Harness 工作台。
2. 点击输入框旁“图片”或“文件”。
3. 图片直接作为原生图片消息发送；普通文件安全进入当前目录 `uploads/`。
4. 文件超过 25 MB 时，放到下载目录并把 `/host/storage/...` 路径告诉 Harness。

### 12.2 首次安装电脑 Relay

1. 用户在电脑保留现有 VS Code + Claude Code + cc switch，不安装电脑 Harness。
2. 安装 Daddy PC Relay，并完成一次性手机配对。
3. Relay 验证 `claude.cmd --version` 和最小调用。
4. 用户选择 Windows 登录后后台启动。
5. 在 Daddy 中看到已配对电脑处于“在线/离线”状态。

### 12.3 从手机派给电脑

1. 用户在 Daddy 明确说“交给电脑 Claude Code”或在目标选择卡选择电脑。
2. Daddy 创建加密任务并显示 `queued_offline` 或 `awaiting_phone_approval`。
3. 用户在手机查看任务说明、目录与模型后点击“执行”。
4. Relay 启动 Claude Code，向手机回传简短进展。
5. 若有新高风险，手机显示第二张确认卡；同意后继续。
6. 完成、失败或中断都如实显示；用户可重试、重新执行或取消。

## 13. 实施顺序

### 阶段 0：电脑 Relay 可行性原型

- 在非真实项目或用户指定测试目录运行 `claude.cmd -p` 最小调用。
- 核验 cc switch 配置继承、`stream-json` 事件、session 标识和费用字段。
- 实作最小权限 MCP 工具，验证同一进程的远程批准、拒绝、超时与取消。
- 模拟 Relay 崩溃、睡眠和网络断开，记录可恢复性边界。
- 只有原型结果明确后，才锁定 PC Relay 的运行方式与手机风险确认能力。

### 阶段 A：手机 Harness 原生附件与补丁框架

- 探测并固定当前 DSH 版本、Web 资源和服务端扩展点。
- 实现图片按钮、原生图片消息发送与 Android 选择器联动。
- 实现普通文件导入端点、`uploads/` 唯一文件命名、25 MB 拒绝策略。
- 实现补丁备份、幂等重打、版本特征校验、失败回滚和验收脚本。

### 阶段 B：手机 Harness 审批档

- 实现安全确认、开发顺畅、全权自动三档的显式设置和持久化。
- 将高风险分类与确认界面绑定。
- 实机验证高风险操作的协议事件；若 Harness/CLI 未提供可靠事件，保守降级并说明。

### 阶段 C：Windows PC Relay

- 创建独立 Relay 工程、配置目录、最小本地状态库与结构化日志。
- 以 `claude.cmd` 做自检和受控任务启动，并采用阶段 0 验证过的权限等待模式。
- Windows 登录自启、在线状态、工作区登记表、相对范围验证和单目录锁。
- 落实 `taskId` / `attemptId` / 事件序列 / 租约围栏 / 基线指纹，不自动重跑过期租约。
- 实现崩溃/睡眠中断记录和恢复策略。

### 阶段 D：加密信箱与 Daddy 路由

- 建立 Supabase 表、严格行级权限、设备配对和端到端加密。
- 实现手机创建任务、远程批准、状态回传与自动清理。
- 将目标选择接入 Daddy 明确委托流程，不改动普通聊天。
- 保持代码小屋现有 UI；只接入必要状态读取，不扩展成复杂项目管理器。

### 阶段 E：端到端验收与发布

- 手机 Harness 图片与普通文件实测。
- 手机离线、电脑离线、电脑睡眠、Relay 崩溃、网络恢复测试。
- 普通任务、初始高风险、执行中高风险、拒绝、取消、重试测试。
- 用已修改 Git 工作区、路径越界、符号链接/Junction、旧 Relay 迟到事件和租约失效进行安全回归测试。
- 验证不泄漏聊天内容、密钥或电脑文件。
- 出具稳定 APK、Relay 安装包/脚本、Harness 补丁包和恢复说明。

## 14. 验收标准

1. 手机 Harness 输入框旁能直接选图并成功发送官方原生图片消息。
2. 手机 Harness 能把 25 MB 以内普通文件安全导入当前目录 `uploads/`，不覆盖、不执行。
3. Harness 更新后补丁可以一键重新应用；不兼容时不损坏工作台。
4. 手机 Harness 的“全权自动”不会对列出的高风险操作静默放行。
5. 电脑未开机时手机派发任务只排队，不消耗模型、不假装运行。
6. 电脑上线后用户可只在手机批准，Claude Code 即可在指定目录执行；不要求触碰电脑。
7. 首次目录访问、高风险操作、取消与过期批准均能在手机准确呈现并生效。
8. 电脑 Relay 只能领取已配对手机发来的任务，且不会读取/上传项目文件或完整聊天。
9. 同一目录不出现并发执行任务。
10. 睡眠、关机、进程崩溃和断网的任务不被静默伪造为完成。
11. 手机 Harness、电脑 Claude Code、Daddy 日常聊天和 Ombre 的模型、记忆及 API Key 保持隔离。
12. 远程高风险审批只在阶段 0 验证的同进程权限等待链路上启用；无法验证时，Relay 必须保守拒绝或要求用户在电脑本地操作，不能伪造“已恢复”。
13. 任何超时租约、旧 attempt 或迟到 Relay 均不能创建第二个同时写入同一目录的 Claude Code 进程。

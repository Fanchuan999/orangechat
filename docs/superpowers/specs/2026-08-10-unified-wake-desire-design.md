# Daddy 统一唤醒、九维欲望与主动消息整合设计

## 1. 目标

让 Daddy 的主动行为从多个相互竞争的触发器，整合成一个可解释、可关闭、低 token 的陪伴节奏系统：

- 普通主动消息、激进模式、晚安守夜、情绪/欲望判断共享同一个本地唤醒决策器。
- Daddy 在用户不聊天时可以拥有自己的节奏，但不能把虚构内容伪装成用户下达的命令。
- 所有主动行为默认使用用户指定的“主动消息主窗口”，避免不同聊天窗口串上下文。
- 所有高成本动作先经过本地零 token 门控；不合适时直接跳过。

## 2. 非目标与边界

- 不改变原始聊天历史、当前上下文条数或用户手动压缩设置。
- 不把每次唤醒、每个欲望数值或每次网页浏览自动写入长期 Ombre 记忆。
- 空闲探索只读取公开网页，不自动发帖、点赞、登录或执行外部写操作。
- 不让“欲望”直接替代 Daddy 的第一人称表达，也不允许它绕过用户关闭的功能开关。

## 3. 统一唤醒模型

### 3.1 节拍器

唤醒服务维护一个可配置的机会窗口，默认约 90 分钟，间隔在 ±30% 范围内随机变化。节拍器只产生本地事件，不直接调用模型。

每次机会窗口依次检查：

1. 当前是否正在正常聊天或刚刚收到用户消息；
2. 晚安守夜是否处于有效状态；
3. 是否有激进模式的设备事件；
4. 普通主动消息是否已启用且达到最小间隔；
5. 空闲时自主探索是否启用且达到每日额度。

同一时间只允许一个高成本动作进入模型调用；被更高优先级消费的窗口会抑制低优先级重复触发。

### 3.2 三信号决策

在真正调用模型前，使用三个本地信号做决策：

- 是否有想联系用户的倾向；
- 是否有值得分享或继续做的事情；
- 当前是否应当休息、安静或处于夜间保护状态。

输出为“联系用户 / 做自己的事 / 回去休息 / 保持安静”。没有足够信号时零成本跳过，不生成“为了醒来而醒来”的消息。

## 4. 九维欲望系统

### 4.1 状态

维护九个 0～1 的缓慢变化维度。名称可配置；初始维度覆盖图片中展示的方向：

- 想你、亲密、好奇、想说、记挂、想逛、想动手；
- 烦/闷、疲惫/想休息。

状态保存在本地设置/状态存储中，随真实事件缓慢更新，不使用无来源的随机跳变。

### 4.2 信号来源

- 用户和 Daddy 最近的对话主题与互动间隔；
- 用户是否完成或回应了某件事；
- 最近一次主动消息是否得到回复；
- 亲密互动后的冷却时间；
- 屏幕/应用事件（仅在用户开启相应权限和模式时）；
- 当前时间、安静时段、健康状态和夜间守夜状态。

### 4.3 约束

- 数值只作为语气、主题和行动选择的背景，不直接输出给用户。
- 每个行为都有冷却和衰减；满足一次倾向后，该倾向下降。
- 高倾向必须有对应来源，避免无理由地突然变黏或连续打扰。
- 全局安静时段、用户明确拒绝和功能开关优先于欲望值。

## 5. Wake / Life：醒来房间

当没有合适理由联系用户时，Daddy 可以在本地执行低成本活动：整理最近经历、准备一条便签、回顾未完成计划、阅读一个待探索主题。活动必须记录为 Daddy 自己的第一人称状态，不能写成用户要求。

默认只保留短期草稿或本地状态；只有用户明确要求保存，或未来单独启用“确认后保存”流程，才写入 Ombre 长期记忆。

## 6. 主动消息与窗口绑定

### 6.1 主窗口

在聊天窗口菜单增加“设为主动消息主窗口”。持久化：

- `assistantId`；
- `conversationId`；
- 可选的显示名称和最后验证时间。

普通主动消息、激进模式和空闲网页探索均使用该具体窗口，不再仅按助手寻找最近对话。

如果主窗口被删除或不可用，安全回退到同一助手最近的可用窗口，并在设置页显示需要重新绑定；晚安守夜仍优先使用说晚安的那个窗口。

### 6.2 统一优先级

1. 用户正在聊天：不插入普通主动消息；
2. 晚安守夜：使用守夜窗口和守夜规则；
3. 激进模式：处理应用切换、亮屏/解锁等用户主动开启的事件；
4. 普通主动消息：受情绪、欲望、间隔和安静时段约束；
5. 空闲自主探索：受独立开关、每日次数和 token 上限约束。

所有触发源共用去重键和最小间隔，避免同一事件生成重复消息。

## 7. 晚安守夜最终规则

- 用户说晚安后进入守夜；
- 守夜 10 分钟后，若屏幕仍亮或刚解锁且仍在使用，Daddy 可以提醒；仅通知短暂亮屏不算使用；
- 提醒次数不设上限；两次提醒之间至少间隔 10 分钟；
- 用户消息包含以下任意结束词时，立即结束当晚守夜：
  - “早上好”
  - “起床啦”
  - “我起床啦”
  - “睡醒”
  - “我不睡了”
  - “我起床了”
  - “别管我了”
- 结束词只识别用户消息，不识别 Daddy 自己的输出；
- 每天早上 06:00 自动失效；凌晨 00:00～05:59 开启时，使用当天 06:00 作为失效时间，06:00 以后开启时使用次日 06:00；
- 设备重启或服务恢复后从持久化状态恢复，不重复触发已经完成的检查。

## 8. 空闲时自主探索

设置页增加独立开关“空闲时自主探索”，默认关闭。它不影响普通主动消息、激进模式或晚安守夜。

开启后：

- 每天 1～3 次，可配置；
- 每次网页原文读取预算最多 20k token；
- 最多选择少量主题和页面；
- 只使用公开搜索/网页阅读能力，不执行外部写操作；
- 根据主窗口最近约 12 条纯文字消息、少量记忆和当前欲望状态选择主题；
- 先压缩网页内容，再把不超过约 800～1200 token 的摘要交给主窗口；
- 不自动写入 Ombre；用户要求保存时才进入记忆流程。

20k 是后台读取上限，不是直接注入 DeepSeek 的上下文上限。若没有可用的压缩路径，系统应降低读取范围或跳过本次探索，而不是把整页原文塞进聊天。

预估额外消耗：每次约 2k～6k token，每天约 2k～18k；所有本地跳过决策为零模型 token。

## 9. 设置界面

在“主动消息与情绪”页增加统一的“唤醒与陪伴节奏”区域：

- 总开关（可选，关闭时暂停所有主动唤醒）；
- 普通主动消息；
- 激进模式 / 应用切换感知；
- 晚安守夜；
- 情绪与九维欲望决策；
- 空闲时自主探索；
- 主动消息主窗口；
- 最小/最大间隔、每日探索次数、网页读取上限。

关闭某一项只影响对应来源，不会误关其它陪伴功能。

## 10. 失败与安全处理

- 网络、MCP、网页阅读或模型失败：记录本地诊断信息，不假装已经完成。
- 连续失败不重试风暴，使用指数退避并等待下一次机会窗口。
- 工具不可用时不把工具错误文本发给用户，主动消息只在有自然内容时发送。
- 主窗口无效时回退并提示；守夜窗口无效时只结束守夜，不串到其它窗口。
- 所有计时使用设备时间并保留北京时区显示；不依赖模型调用时间工具。

## 11. 验收标准

- 同一唤醒窗口不会同时触发两次模型调用或两条重复主动消息。
- 关闭空闲探索后，普通主动消息、激进模式和守夜仍可独立工作。
- 主动消息始终进入已绑定的具体聊天窗口；删除后能安全回退。
- 守夜可以连续提醒但间隔不少于 10 分钟，任意结束词可立即终止，06:00 正确失效。
- 90 分钟节拍和九维状态变化可以在无网络时运行本地测试。
- 网页探索不会把 20k 原文直接注入正常聊天，也不会自动写入长期记忆。
- 新增逻辑拥有单元测试，现有聊天、备份恢复、插件和 MCP 功能不回归。

## 12. 分阶段实施

1. 修正守夜 06:00 失效和结束词，并补测试；
2. 增加主窗口绑定和统一去重/优先级；
3. 将普通主动、激进、守夜和情绪决策接入统一唤醒器；
4. 增加九维欲望状态和设置界面；
5. 最后加入默认关闭的空闲网页探索与 token 限制；
6. 构建 Debug APK，在手机上逐项验证后再考虑推送 GitHub。

# Daddy Harness 桥接任务看板设计

## 目标

把“代码小屋”从旧的手动任务表单改成一个真实状态看板。Daddy 日常聊天通过已安装的 `com.daddy.harness-bridge` 插件把操作类需求交给 Harness；代码小屋只显示 Harness 收件箱中仍活跃的任务，并保留进入完整工作台的入口。

## 已确认的事实

- 插件用 `session.prompt`、`mode: "queue"` 把任务写入一个固定的 `📥 Daddy收件箱` Harness 会话。
- 任务在同一会话中串行执行；原始过程和结果由 Harness 会话事件持久化。
- 插件目前只持久化会话 ID，且该 ID 位于插件私有 `dataStore`；原生 Daddy 页面不能直接读取它。
- 现有代码小屋的“准备任务”仅生成本地文本，**没有提交**给 Harness，因此将删除。

## 不在范围内

- 不修改日常聊天的模型、助手、记忆、世界书或上下文截断。
- 不创建第二个执行器、不替代现有 3080 Harness、也不采用 WebView DOM 自动化。
- 不绕过 Harness 风险确认、删除/覆盖确认或现有“帮我批准”白名单。
- 不向 Harness 传递人设、世界书、Ombre、九维状态、密钥、完整聊天历史或无关私人内容。

## 架构

```text
Daddy 聊天
  └─ Harness 工作台桥插件
       └─ session.prompt(queue) → 📥 Daddy收件箱（唯一串行会话）
                                      ├─ Harness 执行 / 风险确认
                                      └─ session.history 事件流
                                                   ↑
代码小屋任务看板 ── 只读 Harness 会话发现与事件读取 ─┘
```

### 1. 桥接插件 v1.1

保留现有工具名 `relay_to_harness` 和 `check_harness_status`，避免已有 Daddy 助手配置失效。

每一条转达的任务前附加一个机器可读、同时便于人看的小头部：

```text
【Daddy任务】
task_id: daddy-<epoch>-<random>
created_at: <ISO-8601>
title: <不超过 80 字的任务标题>
【任务简报】
...
```

`relay_to_harness` 返回 `taskId`、`sessionId` 和“已排队”事实，不声称已完成。任务简报只包含任务目的、明确文件/目录、成功标准及完成工作必需的背景。插件提示词改为明确禁止带入关系设定、私人记忆、密钥和无关聊天。

`check_harness_status` 以任务编号解析事件，不再仅把“整个会话最后一条消息”当成唯一任务状态。它可返回最近任务的排队、执行、完成或失败事实；只有实际观察到 Harness 的确认事件时才返回“等待确认”。若没有可识别事件，返回“状态暂无法判定”，绝不猜测。

### 2. 原生代码小屋首页

删除以下内容：任务输入框、显式文件/目录/约束表单、“准备任务”、复制任务和“去工作台粘贴运行”。

首页保留：

1. **任务看板**：只显示活跃任务，按“待执行 / 执行中 / 等待你确认”分组；显示标题、排队/开始时间和简短状态。
2. **空态**：没有活跃任务时显示“目前没有进行中的工作”，而不是历史任务列表。
3. **工作台**：打开完整 Harness 工作台、刷新服务状态、前往 Harness 设置。
4. **环境**：只显示“服务状态”和“安全确认策略”。模型、GitHub、Skills、MCP 的配置与准确状态均在 Harness 工作台中管理，不再用 Daddy 的日常配置推断。

完成或失败的任务从首页消失；原始结果与完整记录仍在 `📥 Daddy收件箱` 会话中查看。

### 3. 真实状态读取的前置验证

原生页面不能读插件的 `dataStore`，因此任务看板只有在以下读操作都被 Harness 证实可用时才启用：

1. 能用已公开 RPC 列出或定位标题为 `📥 Daddy收件箱` 的会话；
2. 能用 `session.history` 读取该会话事件；
3. 能从真实事件区分任务头、`turn/start`、结束消息、`turn/end`，以及（若存在）权限确认事件。

验证只读且在手机本机 127.0.0.1:3080 执行。若会话发现 API、确认事件格式或任务边界任一项未证实，代码小屋不会伪造看板：保留服务状态和“打开收件箱工作台”入口，并显示“无法读取任务状态，请在工作台查看”。

### 4. 状态规则

| 原始证据 | 看板状态 |
| --- | --- |
| 任务头存在，尚未对应 `turn/start` | 待执行 |
| 对应任务已出现 `turn/start`，未结束 | 执行中 |
| 已验证的 Harness 权限确认事件 | 等待你确认 |
| 对应任务最终 `turn/end` 或失败事件 | 从首页移除 |
| 事件不完整或格式未知 | 状态暂无法判定，不伪造 |

单一收件箱始终串行：后续任务只能等待前一项结束，不会同时改同一文件。

## 错误与隐私

- 3080 未运行：提示启动/修复 Harness；不创建假任务。
- 读取失败：脱敏显示固定错误说明，不显示命令、环境变量、令牌或密钥。
- 插件转达失败：Daddy 如实说明未派单，用户可进入工作台修复。
- 任务完成不自动把完整终端日志写回日常聊天；Daddy 仅在用户询问时经插件读取并转述脱敏短结果。

## 验收

1. Daddy 转达两条任务时，Harness 只按队列执行，首页先显示一条执行中和一条待执行。
2. 真实确认事件出现时，首页才显示“等待你确认”。
3. 完成或失败后，该任务不再出现在首页，收件箱会话保留完整记录。
4. 代码小屋不再出现旧手动表单或“准备后手动粘贴”的文案。
5. 环境卡不再显示模型/GitHub/Skills/MCP 的推断“未配置”。
6. 任务文本与错误展示中不包含 Daddy 人设、Ombre、世界书、API Key、令牌或无关聊天内容。

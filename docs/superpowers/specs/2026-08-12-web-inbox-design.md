# Daddy 网页来讯设计

## 目标

让应帆主动把手机或电脑浏览器中选定的网页内容交给 Daddy 阅读，并让 Daddy 在当前指定的主聊天窗自然回复。功能不读取浏览器 Cookie、账号或密码，不自动监听浏览历史，也不把原文自动写入 Ombre。

## 范围

本轮包含两条发送路径：

1. 手机浏览器通过 Android 系统分享或“处理文本”把选中的文字或链接交给 Daddy。
2. 电脑 Chrome 扩展把选中的文字或用户确认过的当前页面正文，通过同一 Wi-Fi 下的局域网桥交给 Daddy。

本轮不包含远程公网中转、浏览器自动抓取、网页自动操作、Cookie 读取、桌面屏幕持续感知或自动写入长期记忆。

## 用户体验

### 主聊天窗

网页来讯复用 `ProactiveMessageSetting.primaryConversationId`。用户在任意聊天窗点击“设为主窗口”后，手机和电脑的网页分享都投递到该窗口。

若未设置主窗口，手机端维持当前 Daddy 的分享选助手流程；电脑端拒绝投递并提示先在 Daddy 中设定主窗口。

### 手机端

Android 收到 `ACTION_SEND` 或 `ACTION_PROCESS_TEXT` 后：

1. 若存在主聊天窗，将文本格式化为自然的“网页来讯”消息并直接进入该聊天窗的输入/发送流程。
2. 若没有主聊天窗，保留已有的助手选择页，避免把内容错误地发送到任意对话。
3. 纯链接不自动全文抓取；只有用户明确分享选段或网页阅读器主动读取时才带入正文。

### 电脑端

Chrome 扩展提供一个工具栏入口：

1. 有选区时默认发送选区；无选区时要求用户确认“发送当前页可见正文”。
2. 弹窗预览标题、链接、字数与截断提示。
3. 扩展扫描 Daddy 网页来讯页展示的二维码后，保存当前局域网地址和短期配对凭证。
4. 每次换 Wi-Fi 或连接失败时，用户重新扫描二维码。扩展不得保存 Daddy、Supabase 或 Ombre 的任何密钥。

### 消息外观与限制

投递内容作为普通用户消息出现：

```
【网页来讯】《页面标题》
……用户主动分享的文字……
链接：https://example.com
```

- 选段上限：2,500 个中文字。
- 整页可见正文上限：8,000 个中文字，必须在扩展内二次确认。
- 截断时附加“内容已截断”的短说明。
- Daddy 的回复不暴露传输提示、配对信息或系统指令。
- 原文只作为聊天记录的一部分保存；不会因为接收而自动调用 Ombre `hold` 或 `grow`。

## 技术设计

### Daddy 原生层

新增“网页来讯”设置/插件页，显示：

- 当前主聊天窗名称与跳转/更换入口。
- 当前局域网接收地址、端口、二维码和短期配对凭证。
- 服务状态与最近投递记录（时间、标题、字数、成功/拒绝原因）。

接收端由 Daddy 原生服务实现，而非 QuickJS 独立监听服务。原因是 Android 的前台/后台限制会让纯插件 HTTP 监听不稳定；原生层也能安全地读取当前主聊天窗和调用已有 `ChatService`。

局域网请求使用一个专用端点，例如 `POST /daddy-web-inbox/v1/share`。请求仅允许：

- 局域网地址；
- 有效短期配对凭证；
- 合法 JSON 字段（标题、URL、正文、模式）；
- 长度限制内的正文。

服务不提供读取聊天、列举会话、读取配置或文件的端点。配对凭证可在网页来讯页重新生成，重新生成后旧扩展立即失效。

### Chrome 扩展

扩展仅使用当前标签页的已渲染文字。选段模式使用浏览器选区；整页模式提取可见正文并由用户确认。扩展发送数据到二维码内的局域网 URL，使用 `fetch` POST。

扩展本地只保存：接收 URL、短期配对凭证、最近一次成功的目标名称。它不申请 Cookie、历史记录、下载、后台抓取或跨标签页读取权限。

### 投递与回复

接收成功后，Daddy：

1. 校验主聊天窗仍存在且未在生成中；
2. 创建规范化网页来讯文本；
3. 通过既有 `ChatService.sendMessage` 将它作为用户消息写入该会话；
4. 由该会话既有的人设、世界书、上下文、Ombre/MCP 配置生成正常回复；
5. 写入本地投递记录。

如果目标会话正在生成，接收端返回“忙碌，稍后重试”，不会并发插入导致消息树竞态；Chrome 扩展提供重试按钮。

## 隐私与安全

- 所有电脑到手机的传输限定为当前局域网。
- 配对码不等同于任何既有密码或 API Key；可随时失效。
- 不上传到 Supabase，不使用外部中转服务器。
- 不自动读取网页；必须由用户在浏览器点击发送。
- 不读取 Cookie、账号密码、token 或网页中未渲染的内容。
- 日志仅保留必要元数据和用户已经发送的标题/字数；提供清空入口。

## 错误处理

| 情况 | 处理 |
| --- | --- |
| 未设置主聊天窗 | 不自动发送，提示在 Daddy 聊天页设定主窗口。 |
| 换 Wi-Fi / 手机地址变更 | 扩展提示重新扫描配对二维码。 |
| 凭证无效或已重置 | 返回 401，不显示任何内部配置。 |
| 文本过长 | 在扩展预览阶段截断并明确标记。 |
| 目标聊天正在生成 | 返回可重试的 busy 状态，不写入半条消息。 |
| 接收服务未启动 | Daddy 网页来讯页显示原因和启动按钮；扩展提示无法连接。 |

## 测试标准

1. 已设主聊天窗时，Android `ACTION_SEND` 和 `ACTION_PROCESS_TEXT` 都能自动投递到该会话。
2. 未设主聊天窗时，保留已有助手选择路径。
3. 局域网端点拒绝缺失/错误凭证、超长正文及无效字段。
4. 有效端点把规范化网页来讯写入指定主会话，并只生成一次回复。
5. 会话生成中时不产生并发写入，返回可重试状态。
6. 重置凭证后旧 Chrome 扩展不能再发送。
7. Chrome 扩展的权限清单不包含 Cookie、浏览历史和后台自动抓取能力。

## 非目标

本功能不是 OpenCLI，也不允许 Daddy 控制电脑浏览器、替用户登录网站、点击网页或后台记录浏览行为。那些能力需要单独的 PC Agent 权限模型和可审计授权，不与网页来讯混在一起。

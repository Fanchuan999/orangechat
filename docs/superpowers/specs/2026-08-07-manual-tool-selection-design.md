# 手动工具选择设计

## 目标

让 Daddy 的每位助手能在聊天输入区选择工具发送方式：维持现有的智能节流，或改成只把用户逐项勾选的 MCP 服务与工具型插件发送给模型。这样用户可只开启 Luto 论坛 MCP，其余服务保持关闭，减少工具定义和插件提示词占用的 token。

## 范围

- 在 Assistant 中持久保存手动工具模式、手动选择的 MCP 服务 ID、手动选择的工具插件 ID。
- 保留现有智能节流；手动模式开启时优先于智能节流。
- 手动模式下：
  - 只注册勾选 MCP 服务中的工具；Ombre-Brain 也遵循此规则，不设隐式例外。
  - 只注册勾选工具插件的工具及插件提示词注入。
  - 没有工具定义的纯页面插件仍可正常打开，不受影响。
- 移除「仅本条全部工具」的界面和传递状态。
- 在聊天输入区的工具面板提供一个可向下拖动收起的手势。

## 交互

工具面板保留「智能工具节流」开关，并增加「手动选择工具」开关。两者互斥：打开手动选择会关闭智能节流，反之亦然；两者都关闭时保持旧版的全部工具行为。

启用手动选择后，用户点「选择工具」打开底部清单：

- MCP 服务：每个已配置服务一项开关，保存到 `manualToolMcpServerIds`。
- 工具插件：每个声明了工具的已加载插件一项开关，保存到 `manualToolPluginIds`。
- 手动清单默认为空，避免用户开启该模式后意外继续发送不需要的能力。

## 发送规则

| 模式 | MCP 来源 | 插件来源 |
| --- | --- | --- |
| 全部工具（两个开关都关） | 助手原有 `mcpServers` | 全部工具插件 |
| 智能工具节流 | 助手原有 `mcpServers`，再按关键词过滤 | 按关键词匹配的插件 |
| 手动选择工具 | `manualToolMcpServerIds`，不进行关键词推断 | `manualToolPluginIds` |

所有决定都在本地完成，不添加模型调用，不改变聊天上下文条数、记忆、世界书或 MCP 服务的连接状态。

## 兼容与安全

- 新字段均带空默认值，现有备份和旧 Assistant 配置可直接读取。
- 手动模式不会自动保留 Ombre 或其他 MCP；用户的开关是唯一准则。
- 全部工具与智能节流模式继续使用原有的助手 MCP 服务勾选清单。

# Daddy 思考沉浸化设计

## 目标

让 Daddy 的所有普通聊天与主动消息在思考区尽量使用简体中文，并将通用角色称呼显示为用户偏好的昵称。默认显示为“宝宝”和“Daddy”。本功能不得修改已保存的消息、Ombre 记忆、工具调用参数或发送给模型的历史消息内容。

## 已确认的体验

- 默认开启“思考沉浸化”。
- 默认昵称：用户为“宝宝”，助手为“Daddy”。两个昵称可在“设置 → 显示设置 → 消息显示”编辑。
- 该开关同时控制两件事：
  1. 为模型加入一条固定、简短的简体中文思考约定；
  2. 对展示中的思考文本做角色称呼兜底替换。
- 仅限制思考区。普通回复、引用、代码、工具结果和保存的原始思考不被改写。
- 不调用翻译模型。若某个提供商仍返回整段外语思考，不翻译原文；固定提示会尽量减少这种情况，展示层只保证角色词替换。

## 架构

### 设置与请求层

在 `DisplaySetting` 中新增全局思考沉浸字段。由于现有显示设置以整体 JSON 序列化，新增带默认值的字段能兼容已安装版本的备份与旧设置。

`ThinkingImmersion` 纯 Kotlin 辅助函数提供固定系统提示。`GenerationHandler` 在基础人设之后、记忆与工具提示之前附加它，因此它是所有普通聊天和主动消息共享的稳定前缀。更改昵称或开关只会让下一轮重建一次缓存；后续轮次仍可复用前缀缓存。

### 展示层

`ChatMessageReasoning` 使用同一个纯函数格式化思考正文和加载中的思考标题。它只处理独立的角色词：`user` / `User` / `用户` 与 `assistant` / `AI` / `助手`。技术词如“用户界面”“AI 模型”不得误替换。原始 `UIMessagePart.Reasoning` 保持不变，因此重新发送历史、导出、工具调用签名及 Ombre 写入均不受影响。

### 时间规则纠正（不改 APK 配置）

当前可调用的本地工具只有 `get_time_info`。`get_current_beijing_time` 并不存在；`time_reminder` 是聊天历史时间戳注入，不是可调用工具，也不是实时钟。用户的世界书应改为以 `get_time_info` 作为唯一实时依据；当手机时区为 Asia/Shanghai 时，其结果就是北京时间。

建议文本：

> 涉及当前几点、日期、倒计时、提醒、催促、迟到或“还有多久”时，先调用当前可用的 `get_time_info`，以返回的手机时间为准。不要尝试 `get_current_beijing_time`。`time_reminder` 只是历史消息的时间标记，不是工具，也不能作为当前时间依据；无法调用时须如实说明。

## 错误处理与限制

- 空白昵称回退到默认“宝宝”或“Daddy”，避免出现空替换。
- 关闭开关后，不注入提示且不替换展示文本。
- 模型是否返回可见思考仍取决于提供商响应中是否有 `reasoning_content`、`reasoning` 或 `<think>`。思考沉浸化不会凭空生成思考。

## 验证

- 纯单元测试覆盖：默认提示、关闭行为、自定义昵称、英文/中文角色词替换、技术词保留。
- 现有 `ThinkTagTransformer` 和 OpenAI 解析测试继续通过。
- 构建 companion APK 并确认包名、签名与 v207 覆盖更新一致。
